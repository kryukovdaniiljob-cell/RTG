# Категорийная аналитика РТГ

Система считает категорийную аналитику по товарному портфелю: рентабельность на всех уровнях
иерархии, дефицит (OOS), структуру запаса и готовые списки решений — что вывести, что распродать,
что переместить, что развивать.

На выходе три документа: **аналитическая записка Word**, **Excel с расчётами (27 листов)**
и **интерактивный дашборд**.

---

## Как пользоваться

### Вариант 1. Через сайт GitHub — ничего устанавливать не нужно

1. Откройте папку [`1_ВХОД`](../../tree/main/1_ВХОД) в этом репозитории.
2. Нажмите **Add file → Upload files** и перетащите свежие выгрузки.
3. Нажмите **Commit changes**.
4. Дальше система работает сама: на вкладке [**Actions**](../../actions) появится запуск.
   Через 5–10 минут он закончится.
5. Готовые отчёты — в папке [`3_ОТЧЁТЫ`](../../tree/main/3_ОТЧЁТЫ), в подпапке с сегодняшней датой.
   Нажмите на файл → **Download**.
6. Дашборд всегда доступен по постоянной ссылке:
   **https://kryukovdaniiljob-cell.github.io/RTG/** — она обновляется сама после каждого расчёта.
   Можно также скачать `Дашборд_*.html` и открыть двойным кликом: это автономный файл,
   интернет ему не нужен.

Исходные файлы после расчёта автоматически переезжают в `2_АРХИВ`, чтобы папка `1_ВХОД`
оставалась чистой.

### Вариант 2. На своём компьютере — два ярлыка

1. Положите свежие выгрузки в папку `1_ВХОД`.
2. Двойной клик по **`ЗАПУСТИТЬ.bat`** — расчёт занимает около 80 секунд,
   папка с готовыми отчётами откроется сама.
3. Если нужно обновить онлайн-дашборд — двойной клик по **`ОБНОВИТЬ САЙТ.bat`**.
   Он отправляет только отчёты и дашборд; исходные выгрузки остаются на компьютере.

Исходники после расчёта сами уезжают в `2_АРХИВ`, папка `1_ВХОД` остаётся пустой
и готовой к следующей загрузке.

Нужен установленный [Python](https://www.python.org/downloads/) — при установке обязательно
отметьте галочку **«Add Python to PATH»**. Библиотеки поставятся сами при первом запуске.

## Какие файлы класть в `1_ВХОД`

| Файл | Обязателен | Что даёт |
|---|---|---|
| Сквозная аналитика РТГ | **да** | продажи, запасы, каталог, нормы матрицы |
| Динамика стоков РТГ | желательно | цены за ед. изм. (в сквозной они нулевые) |
| Рабочая матрица пополнения | желательно | актуальные статусы «складское / заказное» |
| Юнит-экономика (по позициям) | нет | готовые диагнозы и решения |
| Юнит-экономика (по складам) | нет | разнесение затрат по складам |

**Имена файлов не важны** — система опознаёт их по составу листов внутри. Дата в названии
может меняться как угодно.

Если структура выгрузки изменится (переехала или пропала колонка), расчёт **остановится
и скажет, что именно не так**, вместо того чтобы молча посчитать неверно.

## Что считается

**Рентабельность.** Ведущая метрика — **GMROI**: валовая прибыль за год, делённая на средний
запас по себестоимости. Порог — стоимость владения запасом (по умолчанию 56,6 % годовых:
хранение 34,6 % + капитал 22 %). Категория с GMROI ниже порога не окупает собственное хранение,
какой бы хорошей ни была её маржа.

Считается на каждом уровне: группа планирования → направление → группа 1 → группа 2 →
группа 3 → бренд → SKU, плюс разрезы по филиалам, типам складов, складам и их пересечениям
с категориями и брендами.

**Дефицит (OOS).** По классической методике: `OOS_incidence`, `DNS`, `Lost_sales`, `Fill Rate`,
`Cycle Service Level`. Дефицитным считается сочетание «SKU × офис × месяц», где норма min
больше нуля, а фактический остаток равен нулю.

**Сегментация.** ABC по обороту, XYZ по стабильности спроса, признак ликвидности,
возраст запаса, статус засола.

**Рабочие списки.** Вывести (запас есть, продаж нет) · Медленные (содержание дороже прибыли) ·
Развивать (ходовые в дефиците) · Переместить (лежит на одном складе, нужно на другом).

## Как править правила

Все пороги и ставки — в файле [`config/settings.yaml`](config/settings.yaml). Это обычный
текстовый файл с комментариями на русском. Правится в Блокноте или прямо на сайте:
откройте файл → карандаш → измените → **Commit changes**. Следующий расчёт пойдёт по новым
правилам.

Что там можно менять: ставки хранения и капитала, порог GMROI, коэффициент возврата покупателя
для расчёта упущенных продаж, границы ABC и XYZ, что считать медленным товаром, условия
попадания в список «развивать».

Периметр категорий (какие направления и группы ваши) — в [`config/scope.json`](config/scope.json).

## Про точность OOS

Сейчас дефицит считается **помесячно**, потому что в исходных выгрузках нет дневной истории
остатков — есть только срез на дату и помесячные итоги.

Система **накапливает** каждый загруженный срез в папке `база`. Через 2–3 недели ежедневных
загрузок появится настоящая дневная история, и точность OOS вырастет сама, без каких-либо
действий с вашей стороны. Поэтому имеет смысл загружать выгрузки каждый день, даже если
отчёт в этот день не нужен.

## Структура репозитория

```
1_ВХОД/      сюда кладёте свежие выгрузки
2_АРХИВ/     обработанные файлы, по датам
3_ОТЧЁТЫ/    готовые Word, Excel и дашборд, по датам
база/        накопленная история остатков
config/      настройки и периметр категорий
docs/        опубликованный дашборд
engine/      расчётные модули
```

Модули: `io_excel.py` — распознавание и чтение файлов · `metrics.py` — метрики и свёртки ·
`reports.py` — Excel · `report_docx.py` — Word · `report_html.py` — дашборд ·
`run.py` — оркестратор.

## Как включена публикация дашборда

Settings → Pages → Source: **Deploy from a branch** → ветка `main`, папка `/docs`.
Файл `docs/index.html` перезаписывается при каждом расчёте, поэтому ссылка всегда показывает
свежие данные. Отдельный деплой через Actions не нужен.

## Важно про данные

Репозиторий **публичный**: всё, что в нём лежит, доступно любому в интернете, а из истории
git удалить это уже нельзя.

Отчёты в `3_ОТЧЁТЫ` содержат только агрегаты — по категориям, брендам и складам.
Персональных данных в них нет (проверено: ни одного ФИО).

А вот **исходные выгрузки содержат ФИО менеджеров с их личными продажами**. Если загружать
их в `1_ВХОД` на публичном репозитории, эти данные станут общедоступными навсегда.
Чтобы этого избежать, считайте локально через `ЗАПУСТИТЬ.bat` и загружайте в репозиторий
только папки `3_ОТЧЁТЫ` и `docs`.
